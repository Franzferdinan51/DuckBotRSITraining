# Amendments after the 2026-10-22 audit

The audit document is a snapshot of the system as found that night; it is not rewritten after the fact. Program changes made afterwards are recorded here, newest first. The canonical program doc (`docs/RSI-PROGRAM.md`) and the skills always reflect the current rules.

## 2026-10-22 (night, latest) — AgentEvolver imports: methods mined from ModelScope's self-evolving agent system

The owner ordered a pass over ModelScope's AgentEvolver (repo + technical report, arXiv:2511.10395; CuES follow-up arXiv:2512.01311). **Platform verdict: methods only** — its current stack is veRL + vLLM on CUDA (8× A100 reference setup), no Apple-Silicon path; this also corrects the 2026-10-19 note that named its older Megatron/SGLang stack. The GRPO machinery does not transfer to an SFT program; its data/judging/experience engineering does, and is now law in the program doc: **feasibility by replay** (checkable synthetic rows ship only if the reference solution executes — execution is the independent verifier); **difficulty-parameterized synthesis + task schemas** for data-poor tracks (environment profile first; ~100 good tasks captured most of their gain — small diverse verified sets beat bulk); **step attribution as row surgery** (GOOD/BAD step labels, truncate at the first BAD step, mine GOOD segments of failed trajectories) + **guidance stripping** (train as you'll serve) + the η≈0.5 mix-balance evidence behind the source caps; **reference-anchored, bounded judging** (score against references, hard zero for off-task content, judge always bigger than the candidate, outcome/execution evidence outranks judge scores — heavy judge weight measurably degraded their long-run results); **experience units** ("when to use" + "content", comparative success-vs-failure pairs, validation before seeding rows, inference-time retrieval for the operator track); **scaffold pinning** per benchmark family; and a **published-numbers caution** on potential-band tops (their field reports gains without significance testing — our gate stays stricter). Lessons recorded with the rules: task generation out-yielded the RL refinements (validates prep-night economics); no multi-generation chain evidence exists there either, so challenger triggers and drift floors stay conservative; pipeline sub-components are load-bearing (ablate before removing); narrow training can harm off-domain work (per-domain floors vindicated again). Wired into the program doc, both agent skills (co-agent v1.6.0, rule 6D), the driver skill, and the prep queue (implementation builds queued as item 12).

## 2026-10-22 (night, latest) — Model potential & saturation: knowing when to stop

The owner: "we should also consider a model's max potential so we know when to stop training because it can't really improve past that point." Every lineage now carries a **potential band** in its ledger — an estimated ceiling for that base on the program's metrics, from named references (base baselines, the frozen teachers' scores on the program's own evals, published best-known results for the base, the external anchor) — and a **headroom** figure (band top − current) reported per version. A chain is declared **saturated** and stops (no more runs, no challengers) when: two consecutive kept versions gain less than the gate margin with battery movement inside noise, OR the head reaches ~90% of the band top, OR the plasticity probe shows the head learning materially worse than base. Saturation is a success state: the final version stays deployed, the slot rotates to a fresher base, the verdict + evidence are ledgered, and revisiting requires new evidence + the owner's call. Wired into the program doc (dedicated section), the lineage template (band + saturation fields), the rotation state (saturation watch), both skills (co-agent rule 13), the driver job (saturation check before planning; headroom in the morning report), and the README.

## 2026-10-22 (night, latest) — The research pass: 18 gaps, several of them ours

The owner ordered an outside check: "find anything we missed in the process, do research online to help." A sourced review of continual fine-tuning practice (sequential-FT forgetting, model collapse, eval methodology, QLoRA merging, curation) returned 18 ranked gaps. The ones that changed the design:

- **The gate was a noise ratchet.** "Kept if it beats its parent" at small held-out sizes cannot distinguish signal from luck (~785 paired items detect a real 5-pt difference; GPQA's 198 give a ±6.6-pt interval). Now: pre-set margin ≥2× paired SE, ties keep the parent, sub-margin wins get one seed-repeat, ≤3 pre-declared checkpoints.
- **Replay composition was wrong.** The 10–15% slice replayed only general data; the evidence replays *previous-task* data. Now ~5–8% general + ~10–20% stratified replay of all prior chunks, with per-chunk probes in the frozen suite.
- **Selection set = certification set.** Nightly keep/discard on the same set inflates every reported gain over months. Now a selection/confirmation split (confirmation touched only at milestones and challenger face-offs, which are judged on it), quarterly rotation, candidate counts logged.
- **No decontamination.** "Benchmark items never trained on" was intent, not a check — and rephrased contamination evades n-grams (a 13B fine-tuned on rephrased MMLU/HumanEval hit GPT-4-level scores; teacher-generated corpora are a documented vector). Now n-gram + embedding top-k against all gate material per source, rate in the manifest.
- **Artifact truth (also settles audit C4).** Merging LoRA into a 4-bit base measurably degrades it; re-quantizing compounds rounding. Now: adapter / bf16-merged / serving artifact scored separately, the gate judges the serving artifact through the production config, and the bf16 merged master is always the lineage parent. ("QAT-style" was also a misnomer — it's QLoRA-style.)
- **Safety was unmeasured.** Benign SFT erodes refusal behavior; LoRA can strip refusals while capability suites pass. The frozen suite gains a pinned refusal + over-refusal domain, under PER-DOMAIN drift floors (one aggregate line masks a collapsing domain), plus non-score drift signals (perplexity, length, distinct-n, refusal rate).
- **Synthetic budget.** Accumulate-alongside-real is the safe regime (replace → collapse); uncapped synthetic share is not licensed even then. Now: capped share, real rows never shrink, per-row provenance, "verified" requires a verifier independent of the generator, tails monitored.
- **Mechanics:** chunks are stratified interleaves (never topical blocks); LR re-warm/re-decay + α=2r + non-increasing rank carry-over; per-row cumulative exposure counter (retire >~4); challenger gets a pre-declared budget; per-lineage max chain length + plasticity probe; judge protocol (pinned judge, both-orders, calibration set); PII erasure path for append-only backups (per-version keys / crypto-shredding — specified, not yet built).
- **Battery corrected to v3:** GPQA-first was the weakest sequencing at 1–12B (floor + widest CI) — demoted to evidence. Lead: IFEval + GSM8K + ARC-C canary + stratified MMLU canary (+ a private perturbed GSM clone; public GSM8K is provably contaminated), then full MMLU, HumanEval+/MBPP+, MATH-500 (level-stratified), BFCL pinned subset (version + mode pinned to the serving stack, per-category). TruthfulQA is not a gate (wrong construct — imitative-falsehood trivia, not hallucination drift; own-domain factuality probe instead). Vision gate: MMBench/SEED + POPE; MMMU-val quarterly only. Milestone full runs carry a pre-declared veto; benchmark nights also score the best current same-size open model as an external anchor.
- **Honest limits of the research itself:** no published study measures ≥3 generations of QLoRA merge→requantize accumulation (the artifact rule rests on single-step measurements + mechanism); no source directly optimizes replay % for LoRA SFT lineages (the composition fix is well-supported, the exact split awaits the program's own ablation); on-hardware benchmark runtimes are estimates until each gets a timed pilot.
- Wired into: program doc (gate bullet, curation §8–10, Benchmarks section, a dedicated Research amendments section), frozen-suite spec (safety domain, per-chunk probes, judge protocol, drift signals), both templates, both agent skills (driver v-current; co-agent v1.4.0 rule 6C), both recurring jobs, rotation state, and this README pass.

## 2026-10-22 (night, later) — Fresh challenger + replay slice; skill libraries as a data source

- **Train-on-top vs train-fresh, settled by evidence:** the owner asked which the program should do and delegated the call ("do whichever is best"), naming his worry: eventual degradation of other areas and loss of general skills over time. Decision: **lineage stays the main line** (the only scheme compatible with chunked multi-night datasets and compounding inside the window; fresh-every-time either forgets earlier chunks or grows past the window), **plus a fresh challenger control** — triggers: two consecutive gate losses, cumulative drift ≥ half the drift line, or every 4th kept version. The challenger trains fresh from base on the chain's accumulated data and faces the chain head at the full gate (target eval + frozen suite + GPQA); winner takes the chain, face-off recorded in the ledger either way. Wired into the program doc (rules bullet + a dedicated section), the training cron, both skills (driver step 5; co-agent rule 6B), and the rotation state.
- **Replay slice:** every curated train set now carries a ~10–15% general-capability replay slice (instruction/reasoning/conversation), proportion recorded in the manifest — the always-on half of the anti-degradation defense (curation §7).
- **Skill libraries are data source family #3 of 5** (program doc, "Skill libraries as training data"): both agents' skills distill into procedural rows, scenario rows, and eval cases. The owner's point about the self-improving co-agent is recorded with its four consequences: a living self-refreshing corpus, skill revisions as before/after improvement trajectories, distillation labor at the source (the co-agent preps his own skills on prep nights — his skill v1.3.1, rule 8), and an improving teacher. Discipline: per-curation snapshots in the manifest, path generalization, privacy screen, verified-outcome preference.

## 2026-10-22 (night) — Benchmarks: the external yardstick, on non-training nights

Prompted by the owner: as models swap and datasets stack up, the program should know what's worth keeping and what's worth removing by measured effect — so standard benchmarks (GPQA Diamond named first) become a standing measurement layer, run as preparation on **non-training nights** rather than burning training windows.

- **Battery v1 = GPQA Diamond** (198 Q) via the fleet's already-tested harness (run driver-side against the LM Studio API; a house 35B reference score of 111/198 = 56.1% exists from 2026-10-08, and the dataset is reachable with the training Mac's HF token — verified live before scheduling). Expansion (MATH-500, HumanEval+, IFEval, MMLU) joins one at a time, only after each runner is verified on a known model.
- **New cron `rsi-benchmark-nights`** (Mon/Wed/Fri/Sun 01:00): work queue = kept versions missing records, then roster bases without baselines (workhorse 9B first). It never trains, stands down when a training/smoke job owns the night or the machine is busy, and restores the LM Studio loaded set exactly. Its first slot collides with the program's smoke night by design — the stand-down rule makes it desk-prep only that night.
- **Role:** benchmarks are *evidence* under the hard gates (target eval + frozen suite still decide on the night). Every kept version gets a record in its lineage ledger's new benchmark table; a crater vs parent triggers the keep/remove review.
- **Keep/remove learning formalized:** the program doc's curation section gains a lifecycle rule — datasets and roster slots earn their keep by measured effect on evals/benchmarks; what repeatedly fails to move the numbers is retired to the archive and noted, never silently reused.

## 2026-10-22 (evening) — Experience mining: successes, Hermes, and HF datasets as first-class sources

Prompted by the owner's question — *"are we making sure to pull data from our failures and successes and Hermes as well, not just the datasets? as well as pulling from HF datasets that are out there?"* Honest state at the time: failures were fully wired; successes were mined only implicitly (via the corpora); Hermes fed the loop mainly through failure appends and the operator corpus; public HF datasets were **not** a named program source at all — despite the fleet already holding several on the external drive from an earlier training era. All four are now explicit:

- **Success ledger created** — `successes.jsonl` beside `failures.jsonl`, same append-only discipline, seeded with 5 verified entries. Only verified outcomes count; every entry carries its proof. Hermes appends his wins as he sees them; the driver appends from chat; gate passes and verified deployments are recorded as model successes.
- **Mining rules** — failures distill to held-out eval cases + corrected-behavior rows; successes distill to positive training rows + operator-corpus material. Success rows are train-side only: eval stays hard (failure cases + frozen suite), never the highlight reel.
- **Hermes is a first-class source** — his session/decision history, fixes, and prep-night distillations feed the loop by rule now (privacy-stripped), in the program doc, both skills, and the driver cron.
- **HF datasets adopted as a source family** — the existing staging tree (`datasets/hf/`: OpenHermes-2.5 subset, glaive-function-calling-v2, SlimOrca subset, s1K, Pasta009, others) is now a sanctioned source under the same pipeline: license + repo id/revision in the manifest, hard quality filter, privacy screen still applied, sample inspection before full curation, overnight downloads only — and a hard line between *use* and *ownership*: never re-upload someone else's dataset or a derivative passed off as original.
- The program doc's curation section now enumerates all four source families (own corpora, fleet experience, HF datasets, teacher-generated material); the overnight driver's SOURCES section matches.
