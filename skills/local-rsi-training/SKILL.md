# Local RSI Training — the overnight small-model improvement loop

Use when: running, prepping, debugging, or reporting an RSI overnight run; curating or backing up a training dataset; deploying a trained adapter into LM Studio; or answering anything about the program's rules. Canonical program doc: `~/workspace/goals/rsi-overnight-small-model-training-program/files/RSI-PROGRAM.md` (Mac copy: `~/mlx-lm-lora/PROGRAM.md`) — read it before acting; this skill is the how, that doc is the law.

## The program in one paragraph
Tue/Thu/Sat, 1:00–10:00 AM ET (training DONE by 10 AM; 09:45 = stop_training), only while Duckets sleeps. One model + one job per night. Every real run executes a written run plan (goal workspace `hidden_files/run-plans/<date>-<target>.md`) prepared in advance — no plan, no run; the night becomes prep that writes the plan. Nothing over 35B is ever trained. Roster: MiniCPM-V 4.7 1B, Gemma 4 E2B/E4B/12B, Ornith 1.5 9B; 27–35B tier is frozen teachers/judges (sole exception: a deliberate coding run Duckets approves separately). **Two engines, chosen per job in the plan:** mlx-lm-lora (text RSI loop) and Unsloth (vision training + any job where it's plainly better) — identical gates on both; Unsloth-the-tool does not un-park Bolt. QAT-style (LoRA on the quantized base) preferred where it helps. Driver cron: `rsi-overnight-run` (Juno side). Hermes has the same orders in its own skill + memory: never start_training outside the program, its 3 AM brain jobs have right of way, and it stops any out-of-window run.

## Pipeline (fixed order, no skipped steps)
0. **Run plan** — a real run needs `run-plans/<date>-<target>.md` (target+job, **parent version** from the lineage ledger, dataset version/Sabrent path + chunk k of m if the material is large, mode, hyperparams, step budget with throughput math proving it fits the window, eval metric vs parent, deploy name `<model>-rsi-v<n+1>`). Missing or incomplete → prep night that finishes it.
1. **Preflight + RAM prep** — `lms ps` quiet (nothing GENERATING; wait/re-check to 04:00 max, then prep night), no other training run live, RAM headroom real (RSS, never memory_pressure free %). Once quiet, FREE THE MACHINE training-mode-style (Duckets' standing order): unload loaded models tonight doesn't need, clear non-essential apps/processes — lifelines (Muse.app, LM Studio, Terminal, SSH/Tailscale, Hermes gateway, AVG, system) never touched. Still short after cleanup → prep night; never force a run onto a loaded machine.
2. **Curate** — `tools/curate_dataset.py RAW.jsonl OUTDIR` (drops malformed/empty/too-short, exact + near dupes; eval split held out FIRST, never trained on; writes manifest.json with counts). **ShareGPT sources (2026-10-23):** the fleet's decision/code corpora are ShareGPT (`conversations`); the tool normalizes them to `messages` at load (`normalize_row`, manifest counts `sharegpt_normalized`). Without it every row silently counted "empty" and curation produced a ZERO-row set — the manifest-eyeball rule caught it; keep eyeballing. **Decontamination scope (2026-10-23):** run `decontaminate.py` against EXTERNAL gate material (frozen suite + benchmarks); do NOT include the curation's own eval split as items — a templated synthetic corpus flags ~48% of its own train rows on shared scaffolding (spot-checked: same templates, different items), while external material flagged 6/16,562. Eval separation is guaranteed by dedupe-before-split. **Research amendments (2026-10-22, PROGRAM.md is the law):** every source is DECONTAMINATED against all eval/frozen/benchmark items (n-gram + embedding top-k — rephrased contamination evades n-grams; rate in the manifest, flagged rows dropped); chunks of a big source are STRATIFIED INTERLEAVES of the whole, never topical blocks; replay = ~5–8% general + ~10–20% stratified replay of ALL prior chunks of the chain; **multimodal floor (second pass, 2026-10-23):** ≥15–20% of every generation's mix is image-bearing rows, counted SEPARATELY from text replay (text rules alone can dilute vision replay to zero while every stated rule is obeyed); a dedicated safety replay slice is kept distinct from general replay; per-row cumulative exposure tracked (retire >~4); synthetic share capped (≤50% default, real rows never shrink generation-over-generation, per-row provenance source/teacher/verifier, "verified" needs a verifier independent of the generator). **Privacy screen (mandatory, Duckets 2026-10-22):** NO private/personal information in ANY set — train, eval, frozen suite, failure rows. Barred: identifiers (real names beyond public handles, email, phone, address, DOB), family/personal-life content, private messages as content, financial/account details, credentials/tokens/keys, local paths, LAN/tailnet addresses. Scrub a row if it stays useful scrubbed, drop it otherwise; the manifest records screened/scrubbed/dropped counts. Why: these models and datasets are shareable artifacts (he publishes to HF — personal data in training data means a share/upload compromises him, and a model can regurgitate memorized personal data), and personal specifics are noise that hurts general quality. Session-history corpora (operator track) are mined for decisions, personal content stripped. If the curated set isn't worth training on, the night is a prep night. **Experience mining rides along (failures AND successes, whole fleet):** distill `~/mlx-lm-lora/failures.jsonl` (Mac) into held-out eval cases + corrected-behavior rows for the target; failure categories steer coverage and chunk priority. Distill `~/mlx-lm-lora/successes.jsonl` into positive training rows + operator-corpus material — success rows are TRAIN-side only, never eval (eval stays hard); only VERIFIED successes are entries, proof included. Both agents feed both ledgers; Hermes is a first-class source (his session/decision history, fixes, distillations), not just the datasets. **Sources overall — five families, one pipeline:** the fleet's corpora; fleet experience (both ledgers); **agent skill libraries** — Juno's skills AND Hermes' skills distilled into procedural/scenario rows + eval cases (snapshot per curation, generalize paths, prefer skills tied to verified outcomes; Hermes is self-improving, so his library is a living corpus whose revisions are improvement trajectories — and he distills his own skills locally on prep nights); public HF datasets staged under `/Volumes/Sabrent/datasets/hf/` (OpenHermes-2.5, glaive-function-calling-v2, SlimOrca, s1K, Pasta009… — license + repo/revision in the manifest, privacy screen still applies, sample-inspect first, overnight downloads only, NEVER re-upload someone else's set or a derivative as original); teacher-generated material from the frozen tier. Tracks: **the MAIN track is actual improvement on everything** — the fleet's real work across the board, fed by the corpora + the failure ledger. Cannabis/CannaAI is one specific track inside it (strains + science Q&A → MiniCPM-V 1B text route / Ornith 9B; own-grow diagnostics set still to build) — a rotation slot, never the program's headline. **RSI operator track (PLANNED, added by Duckets 2026-10-22):** train Ornith 9B on the program itself — run plans, the failure AND success ledgers, Bolt's studio.db run history (16 runs, errors included), and Juno + Hermes training-decision history incl. Duckets' corrections and the decisions that verifiably worked — into a drafting / log-watching operator on its own `<model>-op-v<n>` chain, judged at its own eval gate. It proposes, never fires: the no-start_training-without-Duckets'-order rule binds it exactly as it binds Hermes. First step is a prep-night corpus inventory + curation (eval held out first; backup under `datasets/rsi/ornith-1.5-9b-operator/`).
**AgentEvolver imports (2026-10-22, PROGRAM.md carries the law):** (i) FEASIBILITY BY REPLAY — a synthetic/teacher row with a checkable outcome ships only if its reference solution actually executes (code runs, tool call validates, math recomputes); execution is the independent verifier, judge approval alone doesn't verify. (ii) DIFFICULTY-PARAMETERIZED SYNTHESIS — data-poor tracks get an environment profile (entities/attributes/operations) + a difficulty ladder + reusable task schemas, not free generation; ~100 good tasks captured most of the gain in their sweeps — small diverse verified sets beat bulk. (iii) STEP ATTRIBUTION AS ROW SURGERY — multi-step traces get GOOD/BAD step labels from a frozen-tier judge; truncate at the first BAD step; mine GOOD segments of failed trajectories as positive rows. (iv) TRAIN AS YOU'LL SERVE — rows generated with retrieved guidance enter training with the guidance stripped; no single guiding source exceeds ~half a chunk (their η≈0.5 optimum; more guidance won early, lost late). (v) EXPERIENCE UNITS — distilled ledger entries carry "when to use" (trigger = retrieval key) + "content"; mine comparative success-vs-failure pairs; validated before they seed rows; operator track retrieves units into context at inference (free capability, ships before operator weights). (vi) JUDGING — reference-anchored where a reference exists (hard zero for off-task content), judge always frozen-tier and bigger than the candidate, judge influence bounded: outcome/execution evidence outranks judge scores (heavy judge weight measurably degraded their long-run results).
3. **Back up** — `tools/backup_dataset.py OUTDIR <target>` → `/Volumes/Sabrent/datasets/rsi/<target>/<date>-v<n>/`, SHA-256-verified (hardened 2026-10-23: copies land in a .tmp dir and rename into place only after every file's hash matches, so a failed backup never consumes a version; target validated as a single path component; ALL files in the curated dir copied; free-space precheck; unmounted root fails loudly). No verified backup = no run. Train from the backed-up copy. (mlx-lm-lora wants a data folder with `train.jsonl` + `valid.jsonl`: when staging the run folder from the backup, ALSO copy eval.jsonl → valid.jsonl there; the gate still scores against the untouched eval.jsonl in the backup.)
4. **Validate** — MCP `check_training_config` must pass before `start_training`, always.
5. **Train** — FROM the parent version's **bf16 merged master** (latest verified `<model>-rsi-v<n>` per `hidden_files/lineage-<model>.md`; base for v1 — the bf16 master is always the lineage's source of truth; quantized serving copies are derived, never parents; LoRA-on-quantized is QLoRA-style, not QAT), sized to finish well inside the window (big datasets chunk across nights, one chunk per run); hyperparameter carry-over per the run plan (LR re-warm to a fraction of prior peak + re-decay; α=2r; rank non-increasing along the chain; seeds/data order in the manifest); poll `training_status`/`training_log`; 09:45 = `stop_training`, no exceptions (training done by 10 AM is Duckets' hard rule). **Anti-degradation pair (Duckets, 2026-10-22):** (i) every curated train set carries a ~10–15% general replay slice (see PROGRAM.md curation §7) so general skills rehearse on every run; (ii) the **fresh challenger** — when a chain hits a trigger (2 straight gate losses, drift ≥ half the drift line, or every 4th kept version), a planned sequence trains FRESH from base on the chain's accumulated data and faces the chain head at the full gate (target eval + frozen suite + GPQA); winner takes the chain (a winning challenger is logged as a fresh-restart version), loser is discarded with numbers. Either way the face-off is recorded in the ledger — it's the program's running evidence on whether compounding still helps that model. **Config audit (verified on the Mac, 2026-10-23 — second pass):** driver = mlx-lm-lora **5.9.0** (MCP), TEXT path — mlx-vlm is NOT installed, so a VLM target's vision tower + projector get NO gradients (frozen by construction, grafted back at fuse). Adapters land on all nn.Linear in scope, but scope = `num_layers`: the default **16 of the Ornith 9B's 32 layers** trained only the top half in every run through the smoke AND the original Oct 27 v1 config (amended to 32 with a pre-declared pace check). Rank/scale are NOT first-class MCP parameters — effective values ride driver defaults (**rank 8, scale 10.0**, dropout 0) and are read from each run's `adapter_config.json` into the ledger, never assumed. RULES: num_layers is set deliberately per run plan (default = all layers); the installed build HAS DFT loss, QAT flags, and DPO/ORPO/CPO/GRPO modes (verified in the package source); the package does not pack sequences.
6. **Eval gate + anti-lobotomy guard (Duckets, 2026-10-22; statistics per the 2026-10-22 research pass)** — TWO mandatory post-run tests, no exceptions, all scored on the **SERVING artifact** through the production configuration (adapter / bf16-merged / serving scored separately; serving decides): (a) candidate vs **parent** on the held-out SELECTION eval — kept only on a win ≥ the pre-set margin (≥2× paired SE; ties keep the parent; a sub-margin win earns one seed-repeat; ≤3 pre-declared checkpoints, no fishing; the CONFIRMATION set is touched only at milestones and challenger face-offs, which are judged on it); and (b) the **frozen regression suite** — now including the safety/refusal domain and per-chunk probes, with PER-DOMAIN drift floors vs base (not one aggregate line) plus drift signals (general-text PPL, output length, distinct-n, refusal rate). Plus the **benchmark evidence layer** (Duckets, 2026-10-22): every kept version gets a benchmark record from **battery v3** — the full runner set built and smoke-verified 2026-10-23 and owned by the **local-model-bench** skill (GPQA Diamond evidence-tier, GSM8K, ARC-Challenge, MMLU canary, MATH-500, HumanEval+/MBPP+ with execution grading, IFEval with local instruction checks, BFCL v4 simple in pinned prompt mode, POPE as the vision gate; all run Mac-side over loopback; tier rule — a benchmark counts only where the base beats its floor) recorded in its lineage ledger; benchmarking runs mostly on NON-training nights via cron `rsi-benchmark-nights` (Mon/Wed/Fri/Sun 01:00, stands down when a training/smoke job owns the night, restores the LM Studio loaded set exactly, battery may split across nights per model). **Tier rule (Duckets, 2026-10-23): the FULL battery is baseline/milestone-only — per-run gating uses the GATE tier only (selection set + frozen suite + canary subsets, ≤ ~2 h, inside the night window), so the model stays usable between runs; see the local-model-bench skill's tiers section.** Benchmarks are evidence under the hard gates on the night — AND, per Duckets' winners-only promotion (2026-10-23), the bench record is a removal criterion after the fact: a version that benchmarks weaker than its parent/the chain's others (beyond noise) is removed (archived, struck as a parent, chain head reverts to the last winner), the failure is documented in the lineage + failure ledgers and distilled into eval cases/corrected rows. Only winning models are ever trained on. Benchmark items are eval-only, never training data. Datasets and versions alike earn their keep by measured effect — prep nights retire what repeatedly fails to move eval/benchmark numbers (archive + note in rotation state, never silent reuse). (fixed general-capability set — instruction following, reasoning, coding, tool use, conversation + the failure-ledger eval cases; built once, backed up under `datasets/rsi/frozen-suite/` on Sabrent, NEVER trained on, NEVER edited to make a run pass) scored vs parent AND vs base v0. Winning (a) while regressing on (b) = discarded, same as a gate loss — versions train on top of versions here, and small general losses compound into a lobotomized model. Record parent / base / candidate frozen-suite scores in the lineage ledger after EVERY run; cumulative drift vs base is a named number in the morning report. Any clear regression on a frozen category vs parent fails the candidate; crossing the lineage's pre-set cumulative drift line stops the chain — the next run restarts from base or the last known-good version. Never build the next run on a regression. **Second-pass gate additions (2026-10-23, PROGRAM.md "Second research pass" is the law):** every gate ALSO produces zero-training-cost weight-space candidates — an α-interpolation grid toward the parent (α ∈ {1.0, 0.85, 0.7, 0.55}, bf16, pre-quantization, gated identically; a near-miss discarded at α=1.0 may pass at α<1) and an intruder-dimension spectral audit of ΔW per adapted layer (share of ΔW norm orthogonal to the parent's top singular subspace, trended per generation) with a shrunk-intruder (×0.5) variant as an extra candidate. Gate statistics: paired SEs are CLUSTERED by source template/trajectory/schema; small-n benchmarks report Wilson/Beta intervals; every gate prints its MDE; promotion books the CONFIRMATION-set estimate as the generation's official gain (winner's-curse bookkeeping). Queued builds from the same pass: DFT-vs-NLL challenger pair at the next generation, the RAFT on-policy loop for verifiable domains (500-prompt pilot first), an ORPO/DPO preference stage on ledger GOOD/BAD pairs under its own gate, QAT-at-serving-precision A/B for a final candidate.
7. **Deploy + verified swap** — merge the kept adapter with the bench skill's `fuse_and_stage.py` (fuses bf16, grafts the vision tower back for VL bases — mlx_lm.fuse drops it silently — completes the folder, verifies it), install into the LM Studio library as `<model>-rsi-v<n+1>`, relaunch the app if the new folder isn't indexed yet (LM Studio never rescans at runtime) — close + reopen through GUI computer use (the Mac's desktop control) ONLY, never kill -9 or shell-signal the app (a hard kill corrupts its saved settings; an ignored scripted quit means switch to computer use, not stronger signals), load under guardrails with `lms_preflight.py --load`, and verify IN LM Studio (real prompts incl. eval prompts, image test for vision models — POPE via the bench skill, quality vs parent). Only after it verifies: previous RSI version moves to `/Volumes/Sabrent/lmstudio-archive/` (never hard-delete; the original base always stays). ## Model potential & saturation (Duckets, 2026-10-22)
Every lineage ledger carries a **potential band** (estimated ceiling for that base on our metrics — sources: teacher scores on our evals, published best-known for the base, the external anchor) and **headroom** (band top − current), reported per version. A chain is **saturated** — and STOPS: no more runs, no challengers — when two consecutive kept versions gain less than the gate margin with battery movement inside noise, or the head reaches ~90% of the band top, or the plasticity probe shows the head learning materially worse than base. Saturation is success flattening at a ceiling, not failure: the final version stays deployed, the slot rotates to a fresher base, the verdict + evidence go in the ledger, and revisiting needs new evidence + Duckets' call. **Verifier ceiling (second pass, 2026-10-23):** a verified-synthetic chain plateaus at its verifier's competence (Yi et al., ICLR 2026) — track per-domain verifier-agreement/diversity beside the band, and when a domain saturates, upgrade/diversify its VERIFIER first (execution or self-consistency where only judging existed) before declaring the lineage saturated; judge-scored domains are predicted to peak/reverse while execution-scored domains keep improving.

## Driving the MCP
Server: `/Users/duckets/mlx-lm-lora/.venv/bin/mlx-lm-lora-mcp` (Mac). One-shot driver: `tools/rsi_mcp.py` (runs on the Mac; call it through `~/bin/mac-ssh`):
```
~/bin/mac-ssh "python3 ~/mlx-lm-lora/tools/rsi_mcp.py list-tools"
~/bin/mac-ssh "python3 ~/mlx-lm-lora/tools/rsi_mcp.py check_training_config '{\"config\": {...}}'"
```
Tools: list_training_modes, check_training_config, start_training, training_status, training_log, list_training_runs, stop_training. Handshake fallback/test: `~/mlx-lm-lora/mcp-test.py`. If the driver hangs, check whether the server is waiting on stdin EOF — kill the driver, not the server config; never restart LM Studio to fix MCP. **Driver contract (fixed 2026-10-23):** exit 0 = tool succeeded, exit 3 = the tool itself returned an error (isError — previously printed as success with exit 0), exit 2 = protocol/transport/timeout (300 s default, `RSI_MCP_TIMEOUT`); the server path derives from the home dir (`RSI_MCP_SERVER` overrides). **Eval scoring:** `tools/score_suite.py` scores any suite in the {id, category, prompt, scoring, expected} schema (frozen suite, selection/confirmation sets) — deterministic scorers for exact/exact_answer/exact_format/execution/refusal, pinned frozen-tier `--judge` for checklist/rubric, per-category summary, raw replies always saved. Bench machinery (battery runners, fuse/stage, preflight) lives in the **local-model-bench** skill.

## Memory discipline + gotchas
- Training nights are NOT full training-mode lockdowns (that's for Duckets' big manual runs) — but the Mac discipline still applies: check what's loaded before anything, leave nothing running afterward, downloads (Gemma set) happen overnight only.
- Hermes brain jobs (~3 AM) and Hy-Memory shadow (3:38 AM) share these nights by design — that's why preflight waits instead of forcing.
- A "successful" start_training return is not proof of training: confirm via training_status + log lines (same lesson as the Unsloth zombie runs).
- Adapters that don't face the eval gate don't count. Unevaluated adapter piles are clutter, not progress.
- Smoke night rule: the first run of any new target/toolchain version is tiny and proves the pipeline only — no eval claims, no deployment.
- Benchmark comparability: same harness, same settings, same battery version — a GPQA score from a different harness/config is a different metric. Reference on record: DuckBot Ornith 35B = 111/198 (56.1%), 2026-10-08. Battery expansion (MATH-500, HumanEval+, IFEval, MMLU) only one at a time, runner verified on a known model first.
- Driver invocation: run `rsi_mcp.py` in a FOREGROUND mac-ssh call with a generous yield, one driver at a time. Two concurrent drivers (or a backgrounded one racing a retry) can make the server look hung/EOF — if it ever reports a transport error, wait, check for stray driver processes on the Mac, and retry once cleanly before touching any config.
